Real Analysis Optimization Statistics

Optimization

The study of finding the best solution from a set of feasible options, often by maximizing or minimizing an objective function.

Linear Programming (LP) Formulation

Example: a factory picks liters of pink peppermint (x₁) and blueberry (x₂) ice cream to maximize profit under ingredient limits.

The factory wants to maximize profit from the liters it produces: $5 profit per liter of peppermint, $4 per liter of blueberry.

$$\max\quad 5\textcolor{#e64980}{x_1} + 4\textcolor{#3b6bd6}{x_2}$$

There's only so much milk on hand, so milk used across both flavors can't exceed the supply.

$$3\textcolor{#e64980}{x_1} + 4\textcolor{#3b6bd6}{x_2} \leq 24$$

Peppermint extract only goes into the peppermint flavor, and there's a limited supply of it.

$$\textcolor{#e64980}{x_1} \leq 6$$

Fresh blueberries are limited too, capping how much of that flavor can be made.

$$\textcolor{#3b6bd6}{x_2} \leq 5$$

You can't produce a negative number of liters.

$$\textcolor{#e64980}{x_1}, \textcolor{#3b6bd6}{x_2} \geq 0$$

The shaded region above is every feasible production plan. The best one sits at a corner — here, (x₁, x₂) = (6, 1.5), for a profit of 36.

Integer Linear Programming (ILP) Formulation

Example: a breakfast budget — pick green eggs (x₁) and slices of ham (x₂) to maximize protein without busting a €3 budget.

The goal is to maximize total protein from breakfast.

$$\max z = 7\textcolor{#2f9e44}{x_1} + 10\textcolor{#c2525c}{x_2}$$

Green eggs and ham each cost money, and the morning budget is fixed.

$$0.7\textcolor{#2f9e44}{x_1} + 0.9\textcolor{#c2525c}{x_2} \leq 3$$

You can only buy a whole number of eggs or ham slices — no fractions, which is what makes this an integer program.

$$\textcolor{#2f9e44}{x_1}, \textcolor{#c2525c}{x_2} \in \mathbb{Z}_{\geq 0}$$

The shaded region above is the continuous feasible area; the dots are the integer points inside it. The best integer point is (x₁, x₂) = (3, 1), for a value of 31 — not the same as rounding the LP relaxation's optimum of (0, 3.33), which scores 33.33.

A second shape of ILP, common enough to deserve its own pattern: assignment. Two workers {1, 2} must each be assigned to exactly one of two tasks {A, B}, at a known cost per worker-task pair, minimizing total cost.

$$x_{ij} \in \{0, 1\}, \quad x_{ij} = 1 \iff \text{worker } i \text{ is assigned to task } j$$

Each worker takes exactly one task, and each task goes to exactly one worker — a row sum and a column sum, both pinned to 1.

$$x_{1A} + x_{1B} = 1,\quad x_{2A} + x_{2B} = 1,\quad x_{1A} + x_{2A} = 1,\quad x_{1B} + x_{2B} = 1$$

With costs c₁ₐ = 4, c₁ᵦ = 2, c₂ₐ = 3, c₂ᵦ = 5, the objective to minimize is:

$$\min\ 4x_{1A} + 2x_{1B} + 3x_{2A} + 5x_{2B}$$

The binary variables and one-per-row/one-per-column constraints are the signature of an assignment formulation — worth recognizing on sight, since the same pattern covers scheduling (one shift per worker, one worker per shift) with no change beyond relabeling.

Simplex

The simplex method never looks inside the feasible region — it starts at a corner and walks along the edges toward a better one.

Simplex starts at a feasible vertex — here, (0, 0) — then repeatedly pivots to an adjacent vertex along the boundary whenever that improves the objective: (0, 0) → (6, 0) → (6, 1.5). It stops once no neighboring vertex scores higher, landing on the optimum with a profit of 36.

The algorithm, as a repeatable procedure:

  1. Add a slack variable to each ≤ constraint, turning it into an equality.
  2. Set up the initial tableau with every slack basic and every structural variable at zero.
  3. Check optimality: if every coefficient in the objective row is already non-negative, stop — the current corner is optimal.
  4. Otherwise, choose the entering variable: the non-basic variable with the most negative objective-row coefficient.
  5. Choose the leaving variable with the minimum ratio test: among rows with a positive entry in the entering column, pick the one with the smallest RHS-to-coefficient ratio.
  6. Pivot — scale the chosen row so the entering variable's coefficient becomes 1, then clear that column from every other row, including the objective row.
  7. Repeat from step 3.

The same walk, numerically: the tableau starts with every slack basic, then pivots one variable in and one out per step.

Two-Phase Simplex

Add a minimum order to the same ice cream line: at least 2 liters total must be made, or it isn't worth running the machine.

$$\textcolor{#e64980}{x_1} + \textcolor{#3b6bd6}{x_2} \geq 2$$

Now the origin is infeasible, so simplex has nowhere obvious to start. Phase one ignores profit and just hunts for any feasible corner, using an artificial variable to patch the constraint; phase two then optimizes real profit from there.

The minimum-order line slices the corner nearest the origin off the feasible region, so (0, 0) is no longer a valid start. Phase one jumps straight to (2, 0) instead; phase two then walks (2, 0) → (6, 0) → (6, 1.5) to the same optimum, a profit of 36.

The procedure, building on ordinary simplex:

  1. For any constraint that isn't already ≤ with a non-negative right-hand side, add a surplus variable and an artificial variable to force an equality.
  2. Phase one: temporarily minimize the sum of the artificial variables, using the same entering/leaving/pivot rules as ordinary simplex, starting from the tableau where the artificials are basic.
  3. If phase one reaches zero, every artificial variable has left the basis (or sits at zero) — a feasible corner of the real region has been found. If it can't reach zero, the original problem is infeasible.
  4. Drop the artificial variables' columns, restore the real objective row, and recompute it against the current, now-feasible basis.
  5. Phase two: run ordinary simplex from there, pivoting on the real objective until every coefficient is non-negative.

Getting a Dual from a Primal

Every primal has a dual: a max problem's dual is a min problem, one dual variable per primal constraint and one dual constraint per primal variable.

Start from the ice cream factory's primal LP:

$$\max\quad 5\textcolor{#e64980}{x_1} + 4\textcolor{#3b6bd6}{x_2} \quad \text{s.t.} \quad 3\textcolor{#e64980}{x_1} + 4\textcolor{#3b6bd6}{x_2} \leq 24,\ \ \textcolor{#e64980}{x_1} \leq 6,\ \ \textcolor{#3b6bd6}{x_2} \leq 5$$

Building the dual, one piece at a time:

  1. Flip the objective direction — max becomes min.
  2. Give each primal constraint its own dual variable: y₁ for the milk constraint, y₂ for the peppermint constraint, y₃ for the blueberries constraint.
  3. Each primal constraint's right-hand side becomes that variable's objective coefficient: 24, 6, and 5 turn into min 24y₁ + 6y₂ + 5y₃.
  4. Give each primal variable its own dual constraint: one for x₁, one for x₂.
  5. Each primal variable's column of constraint coefficients becomes a dual constraint's row, and that variable's objective coefficient becomes the dual constraint's right-hand side. x₁'s column is (3, 1, 0) with objective coefficient 5, giving 3y₁ + y₂ ≥ 5. x₂'s column is (4, 0, 1) with objective coefficient 4, giving 4y₁ + y₃ ≥ 4.

Put together, that's the dual:

$$\min\ 24y_1 + 6y_2 + 5y_3 \quad \text{s.t.} \quad 3y_1 + y_2 \geq 5,\ \ 4y_1 + y_3 \geq 4,\ \ y_1, y_2, y_3 \geq 0$$

Rather than re-running simplex on it, read the solution off the primal's already-known optimal corner, (x₁, x₂) = (6, 1.5). Both x₁ and x₂ are positive, so both dual constraints must hold with equality; the blueberries constraint x₂ ≤ 5 isn't tight there (1.5 < 5), so y₃ must be 0.

$$4y_1 + y_3 = 4,\ y_3 = 0 \ \Longrightarrow\ y_1 = 1, \qquad 3y_1 + y_2 = 5 \ \Longrightarrow\ y_2 = 2$$

That gives y₁ = 1, y₂ = 2, y₃ = 0 — a dual objective of 24(1) + 6(2) + 5(0) = 24 + 12 = 36, exactly matching the primal's optimal profit.

Weak duality keeps the primal's rising values below the dual's falling ones at every step; strong duality is the special fact that, at the optimum, they meet exactly.

Complementary Slackness

At the optimum, a primal variable and its matching dual constraint can't both be slack — for each pair, at least one of the two must be exactly zero.

$$\textcolor{#e64980}{x_1} \textcolor{#7B4B8C}{>} 0 \implies \text{dual constraint 1 binds}, \qquad y_3 = 0 \text{ since blueberries is slack}$$

The same argument is how a shortest-path tree gets proven optimal, not just plausible. Written as an LP, shortest path from s to t minimizes total edge weight subject to flow conservation at every node; its dual assigns each node v a potential y(v), with one dual constraint per edge:

$$y(v) - y(u) \leq w(u,v) \quad \text{for every edge } (u,v)$$

Complementary slackness says every edge actually carrying flow in the shortest-path tree must have its dual constraint bind exactly, y(v) = y(u) + w(u,v) — otherwise that edge's primal flow would have to be zero. A set of Dijkstra distances d(·) is exactly such a potential: d(v) ≤ d(u) + w(u,v) for every edge, with equality precisely on the tree edges Dijkstra used. That tightness-only-on-tree-edges is the certificate — it's what lets a graded shortest-path answer be checked for optimality without re-running the algorithm, the same way the ice cream example above checks an LP corner.

Gomory Cutting Planes

A Gomory cut adds a valid inequality — one that every integer point already satisfies — that slices a fractional corner off the LP relaxation, shrinking it toward the true integer hull.

Take the green-eggs-and-ham budget constraint. The Gomory split needs every variable in its row — including the slack — to be integer-valued at integer solutions, so scale away the decimals first.

$$0.7\textcolor{#2f9e44}{x_1} + 0.9\textcolor{#c2525c}{x_2} \leq 3 \quad\Longrightarrow\quad 7\textcolor{#2f9e44}{x_1} + 9\textcolor{#c2525c}{x_2} + s_1 = 30$$

At the LP optimum, ham (x₂) is the basic variable and it's fractional. Its simplex tableau row:

$$\textcolor{#c2525c}{x_2} + \tfrac{7}{9}\textcolor{#2f9e44}{x_1} + \tfrac{1}{9}s_1 = \tfrac{10}{3}$$

Gomory's cut keeps only the fractional part of each coefficient and of the right-hand side. Any integer solution still satisfies it, but the current fractional vertex can't — plugging in x₁ = s₁ = 0 gives 0 ≥ ⅓, which is false.

$$\tfrac{7}{9}\textcolor{#2f9e44}{x_1} + \tfrac{1}{9}s_1 \geq \tfrac{1}{3} \quad\Longrightarrow\quad 7\textcolor{#2f9e44}{x_1} + s_1 \geq 3$$

Substituting the slack back out in terms of the original variables collapses this to a single bound on ham, independent of eggs — exactly the cut drawn below.

$$7\textcolor{#2f9e44}{x_1} + (30 - 7\textcolor{#2f9e44}{x_1} - 9\textcolor{#c2525c}{x_2}) \geq 3 \quad\Longrightarrow\quad \textcolor{#c2525c}{x_2} \leq 3$$

The faint dashed outline above is the LP relaxation before any cuts. Since ham must be a whole number, x₂ ≤ 3.33 is really x₂ ≤ 3 — a valid cut that removes no integer point, but slices off the fractional corner and shrinks the relaxation's optimum from 33.33 down to 33, a step closer to the true integer optimum of 31.

Dijkstra's Algorithm

Dijkstra grows a shortest-path tree one node at a time, always settling the closest unvisited node next.

Each node keeps a running best-known distance from the source, improved by relaxation through every settled neighbor:

$$\text{dist}(v) \leftarrow \min\big(\text{dist}(v),\ \text{dist}(u) + w(u,v)\big)$$

Whenever a relaxation actually lowers dist(v), it also records prev(v) = u — the neighbor that achieved the new best distance. The algorithm only ever outputs distances directly, but the path itself is recovered by walking prev pointers backward from the target to the source and reversing that walk.

Complexity and NP-Completeness

P is every problem solvable quickly; NP is every problem whose solution can be checked quickly; NP-complete problems are the hardest problems in NP, each able to encode any other via a reduction.

If any single NP-complete problem (like SAT) turns out to be solvable quickly, a reduction lets every problem in NP ride along and be solved quickly too — that's exactly the open question "does P = NP?".

A worked reduction, proving Independent Set is NP-complete given that Vertex Cover already is: a set S ⊆ V is independent exactly when no edge has both endpoints in S — equivalently, every edge has at least one endpoint outside S, which is exactly what it means for V∖S to be a vertex cover.

$$S \text{ independent} \iff V \setminus S \text{ is a vertex cover}$$

So graph G has an independent set of size k iff G has a vertex cover of size n − k (n = |V|). The reduction is just that threshold swap — same graph, flip k to n − k — computable in constant time, so it's trivially polynomial. Combined with Independent Set already being in NP (checking a candidate set is independent takes one pass over its edges), this proves Independent Set is NP-complete: at least as hard as a known NP-complete problem, and itself verifiable in polynomial time.
